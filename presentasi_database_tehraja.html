Technical Overview

Tech Stack Utama

  • Database Backend: Firebase Realtime Database (NoSQL)

Mengapa Firebase RTDB? NoSQL

Dibandingkan database relasional tradisional (MySQL/PostgreSQL)

1. Sinkronisasi Real-Time Kritis

Operasional POS membutuhkan responsivitas sub-detik. Saat pelanggan memesan via HP, pesanan harus langsung muncul di layar KDS kasir tanpa *refresh*. Firebase RTDB menggunakan protokol WebSocket (pub/sub) yang secara *native* mendukung *live-sync*.

2. Skema Dokumen Fleksibel

Satu pesanan minuman memiliki struktur dinamis (Gula: Less, Es: Normal, Topping: Boba). Menyimpan *JSON tree* secara utuh di NoSQL jauh lebih cepat daripada melakukan *JOIN* berulang kali pada puluhan tabel di SQL.

Robust Offline-First

"Transaksi tidak boleh berhenti walau internet mati."

  • Zustand Buffer: Semua transaksi diproses di memori klien dengan kecepatan instan.
  • Offline Queue: Saat koneksi terputus, data diisolasi ke *Local Storage*. Kasir tetap bisa input pesanan dan cetak struk via Bluetooth lokal.
  • Background Sync: Begitu sinyal kembali, agen pekerja (Service Worker) melakukan injeksi balik (*flush*) seluruh antrean ke Cloud secara atomik, tanpa *race condition*.

Mengapa Zustand? Client State

  • Selective Rendering: React Context API merender ulang seluruh komponen jika ada perubahan data. Zustand hanya merender komponen yang berlangganan spesifik. Ini mencegah layar kasir (yang memiliki ratusan tombol) menjadi lambat (*lag*).
  • Bundle Size Minimal: Tanpa *boilerplate* rumit ala Redux. Menjaga aplikasi tetap ringan (*< 5MB*) untuk diinstal pada HP kasir spesifikasi rendah.

Struktur Data NoSQL

Pendekatan *Controlled Denormalization*

  • Node /products : Menyimpan master data (ID, nama, harga dasar, kategori).
  • Node /orders : Mencatat header transaksi (pelanggan, total, tipe pesanan) & memiliki relasi dinamis ke *items*.
  • Data Historis /items : Menyalin *Snapshot* produk (nama & harga saat dibeli). Jika harga produk master naik esok hari, data laporan keuangan hari ini tidak akan rusak/berubah.

Fase Skala Nasional (B2B)

Proyeksi Arsitektur Polyglot Persistence untuk ratusan cabang:

  • PostgreSQL (Master DB): Akan menangani agregasi analitik berat lintas-cabang (Role-Based Access, Laporan Laba/Rugi Konsolidasi).
  • Firebase / Redis: Diturunkan fungsinya murni sebagai Live Message Broker untuk komunikasi interaktif dalam kedai.
